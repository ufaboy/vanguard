Under the Hood: a Three.js WebGL Tank Game

BATTLE TANK is a free 3D isometric tank game that runs entirely in the browser. This page explains how it is built: a Three.js and WebGL renderer, plain JavaScript modules without a bundler, and a set of techniques that keep a destructible 1,600-cell arena running smoothly on ordinary laptops.

A Zero-Bundler Vanilla JavaScript Stack

The game is written in plain JavaScript using native ES modules, loaded directly by the browser through an import map. There is no framework, no TypeScript and no build step: the files you download are the files we edit. The only runtime dependency is Three.js, and a small script copies just the Three.js modules the game actually imports into the site, so players never download unused code.

The whole site is static HTML served from a CDN. Every page outside the battlefield, including this one, is a normal HTML document with its text in the markup, so it loads instantly and is easy for search engines to read. Only the battlefield page starts the WebGL engine.

Rendering a Destructible Arena

INSTANCING Batched Terrain Tiles

Walls, crates, trees and decorations are grouped by mesh and drawn with instanced rendering. Thousands of blocks share a handful of draw calls instead of one per object.

TEXTURES Procedural Textures in a Worker

Ground and wall textures are generated procedurally in a Web Worker, keeping the main thread free while a mission loads.

MODELS KTX2 and Draco GLB Models

Tank and boss models are modeled in Blender and exported as GLB files with Draco-compressed geometry and KTX2 GPU-compressed textures, capped at 512 px, so they load fast and use little video memory.

EFFECTS Pooled Particle Effects

Explosions, smoke, sparks and tracers come from object pools and a shared texture atlas, so heavy firefights do not create garbage-collection stutter.

Running on Any Machine

At startup the engine checks whether WebGL is hardware-accelerated or running on a software renderer such as SwiftShader or llvmpipe. On software WebGL it switches to a lighter rendering path, so the game still runs on older laptops, virtual machines and computers with disabled graphics acceleration. Players can also choose a graphics quality preset and an FPS cap in the settings.

Simulation and Enemy AI

Gameplay rules are kept in pure simulation modules separate from rendering. Tank stats are computed from a hull base plus five upgrade tracks; damage uses per-side armor and penetration; and enemy tanks plan routes with A* pathfinding on the grid, check line of sight cell by cell, and choose tactical positions based on cover, forest and chokepoints.

A squad director limits how many enemies may shoot at you at once and spreads attackers around you, so fights feel coordinated rather than chaotic. You can watch the AI think with the in-game telemetry overlay (F3), which shows each tank's role, current order and planned path. The Enemy Guide describes all 12 enemy roles.

Try It Yourself

The best way to see the engine is to play. Open the Campaign in Chrome, Edge, Firefox or Safari and start the first mission. Patch notes for every release are listed in the Changelog, and bug reports are welcome on the Contact page.
